## 전체 구조

CodeInsight는 TypeScript 모노레포로, 패키지 4개로 구성됨:

```
packages/
├── frontend/     → React 19 + Vite (UI & 시각화)
├── backend/      → Node.js + Fastify (API & 인증)
├── shared/       → Zod 스키마 & 타입
└── simulators/   → 언어별 코드 실행 엔진
```

데이터 흐름은 단순함:

**코드 입력 → 시뮬레이터 → 실행 트레이스(JSON) → 시각화**

레슨 모드에서는 트레이스가 미리 만들어진 JSON 파일임. 플레이그라운드 모드에서는 Docker 컨테이너 안에서 코드를 실행해서 트레이스를 그 자리에서 만들어냄.

## 프론트엔드: React 19 + Vite

### 왜 React 19냐면

성능이 개선됐고 생태계가 충분히 성숙해있어서 선택함. 시각화 컴포넌트 자체가 인터랙션이 많음 — 변수 애니메이션, 스택 프레임 증가, 포인터 연결 같은 것들. React의 재조정(reconciliation) 모델이 이런 부분을 잘 처리해줌.

### 상태 관리: Redux 대신 Zustand

세 가지 옵션 비교해봤음:

| | Redux | Context | **Zustand** |
|---|---|---|---|
| 보일러플레이트 | 많음 | 적음 | **거의 없음** |
| DevTools | 있음 | 없음 | **있음** |
| 성능 | 양호 | 리렌더링 문제 있음 | **선택적 구독** |
| 학습 곡선 | 가파름 | 낮음 | **낮음** |

보일러플레이트 거의 없이 Redux급 기능 쓸 수 있어서 Zustand 골랐음. 스토어 파일 하나로 인증 상태, 레슨 진행도, UI 설정 다 관리함.

### TailwindCSS

후회 없음. 유틸리티 기반 CSS가 스타일을 컴포넌트 옆에 붙여두게 해줘서 "이 스타일 어디서 온 거임?" 문제가 사라짐. 다크/라이트 모드 테마는 CSS 커스텀 프로퍼티로 처리했는데 그냥 잘 됨.

### Vite

Create React App에서 마이그레이션하고 나서 빌드 시간이 ~45초에서 ~3초로 줄었음. HMR은 거의 즉각적임. 돌아갈 생각 없음.

## 백엔드: Fastify + Prisma

### Express 대신 Fastify 고른 이유

Express가 기본 선택지긴 한데 Fastify가 실질적인 장점이 있음:

- **2-3배 빠름** (스키마 기반 직렬화 덕분)
- **내장 유효성 검사** (JSON Schema 사용, 우리는 Zod + fastify-type-provider-zod 씀)
- **플러그인 시스템**이 깔끔한 아키텍처를 유도함
- **TypeScript 우선** 설계라 타입 추론이 잘 됨

### Prisma ORM

PostgreSQL 레이어는 Prisma가 맡음. 스키마를 코드로 관리하니까 DB 구조가 애플리케이션 코드랑 같이 버전 관리됨. 마이그레이션이 결정적(deterministic)이고 리뷰 가능함.

단점은 있음: Prisma 클라이언트 번들이 크고 복잡한 쿼리는 raw SQL보다 느릴 수 있음. 근데 우리 용도(주로 심플한 CRUD에 조인 약간)에서는 개발 편의성이 이김.

### Zod으로 유효성 검사

모든 API 입력은 `shared` 패키지에 있는 Zod 스키마로 검사함. 같은 스키마가 프론트엔드(폼 입력)랑 백엔드(요청 바디) 양쪽에서 다 쓰임. 단일 진실 공급원(single source of truth).

## 시뮬레이터: Docker 샌드박스

제일 핵심이고 복잡한 부분임. 유저가 플레이그라운드에서 `system("rm -rf /")` 쓰면:

1. 안전하게 실행해야 함
2. 실행 트레이스를 캡처해야 함
3. 의미 있는 시각화 데이터를 돌려줘야 함

언어마다 자체 시뮬레이터가 있음:
- **C**: AST 파싱해서 메모리 연산 시뮬레이션 (스택/힙 할당)
- **JavaScript**: 실행 컨텍스트, 스코프 체인, 이벤트 루프 추적
- **Java**: JVM 메모리 모델링 (메서드 영역, 힙, 스택 프레임)
- **Python**: 참조 그래프랑 이름 바인딩 추적

플레이그라운드 모드는 이걸 전부 엄격한 격리가 적용된 Docker 컨테이너로 감쌈. 보안 관련 자세한 내용은 [3편: Docker 샌드박스 보안](/2026-02-27-CodeInsight-Docker-Security/)에서 다룸.

## 인프라

### Render

전체 스택이 Render에서 돌아감:
- **프론트엔드**: 정적 사이트 배포 (빌드 + CDN)
- **백엔드**: Docker 웹 서비스, 오토스케일링
- **데이터베이스**: 관리형 PostgreSQL

`main`에 푸시하면 자동 배포 트리거됨. 프론트엔드 빌드는 ~2분, 백엔드는 Prisma 마이그레이션이랑 시딩 포함해서 ~5-10분 걸림.

### DB + JSON 하이브리드 구조

핵심 아키텍처 결정 중 하나: 레슨 **메타데이터**는 PostgreSQL에, 레슨 **콘텐츠**(코드, 단계, 설명)는 시작할 때 메모리에 올려두는 JSON 파일에 저장함.

왜 나눴냐면:
- JSON 콘텐츠 조회가 DB 쿼리보다 ~100배 빠름 (0.1ms vs 5-20ms)
- 콘텐츠가 Git으로 버전 관리됨
- 구조(어떤 레슨이 있는지)는 DB에서 관계형 쿼리로 처리
- 내용(각 레슨이 뭘 가르치는지)은 JSON에서 빠르게 읽어옴

## 배운 것들

1. **일단 되는 가장 단순한 걸 만들어라.** 초기 버전에는 Docker도 없었음 — 그냥 정규식 기반 코드 검증기였음. 보안상 허점이 있었지만 빠르게 출시할 수 있었음.

2. **모노레포는 처음부터 구성해라.** 프론트엔드랑 백엔드 사이에서 타입을 공유하니까 버그 한 범주가 통째로 사라졌음.

3. **성급하게 최적화하지 마라.** JSON 콘텐츠 캐시는 프로파일링으로 DB 읽기가 병목이라는 게 확인된 다음에 추가한 거임. 미리 한 게 아님.
