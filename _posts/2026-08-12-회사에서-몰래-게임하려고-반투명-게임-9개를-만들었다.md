**회사에서 몰래 게임** 좀 하고 싶은데, 또는 독서실에서 **공부하다가 잠깐** 쉬고 싶은데
게임 창을 띄우면 티가 남. 브라우저 게임은 탭이 눈에 띄고, 알트탭은 화면이 확 바뀌어서
옆에서 보면 바로 앎. 흔히 말하는 **월루**용으로 쓸 만한 게 의외로 마땅치 않음.

그래서 만듦. **반투명하게 깔려 있고, `ESC` 한 번이면 작업표시줄로 쏙 들어가는 게임 런처**임.
게임 9개가 창 하나에 들어있음. 파이썬 기본 라이브러리(tkinter)만 써서 설치할 것도 없음.

## 뭐가 들어있음

| # | 게임 | # | 게임 |
|---|---|---|---|
| 1 | 테트리스 | 6 | Triple Town |
| 2 | 수박게임 | 7 | 네모로직 (1,500판) |
| 3 | 뿌요뿌요 | 8 | Flood It (60단계) |
| 4 | 2048 | 9 | 소코반 (200판) |
| 5 | Threes! | | |

`M` 누르면 고르는 화면 나오고, 숫자키 `1`~`9`로 바로 감.
**9개 판이 각자 따로 저장돼서** 이거 하다 저거 갔다 와도 하던 자리 그대로임.

레벨 있는 게임(네모로직·소코반·Flood It)은 `,` `.` 로 원하는 판까지 바로 건너뜀.
1,500판을 넣어 놓고 한 판씩만 넘어갈 수 있으면 뒷판 볼 길이 없으니까.
네모로직은 `S` 키로 **10x10 / 15x15 / 20x20** 을 고르고, 크기마다 진행도가 따로 쌓임.

## 핵심은 게임이 아니라 '숨기기'

솔직히 게임이야 널렸음. 이걸 만든 이유는 **안 들키는 것**임.

### 1. 반투명

기본 55%인데 `[` `]` 로 조절되고, 메뉴 화면의 **투명도 바를 마우스로 끌어도** 됨.
20%까지 내리면 뒤에 있는 문서가 비쳐 보여서 곁눈질로는 잘 안 보임.

배경을 어둡게 덮지 않아서 화면 전체가 어두워지는 티도 안 남.

### 2. `ESC` = 작업표시줄로

`ESC` 누르면 **종료가 아니라 작업표시줄로 내려감.** 판도 점수도 그대로 살아있음.
다시 꺼낼 땐 `F8`.

급해서 `ESC`를 눌렀는데 판이 날아가면 억울하니까 `ESC`는 종료가 아니게 해놨음.
끌 때는 `Ctrl+Q` 또는 그냥 창 닫기 버튼. 어느 쪽이든 진행 상황은 저장됨.

### 3. `H` = 더 빠른 숨기기

사실 실전에서 제일 많이 쓰게 되는 건 이거임.
`ESC`는 창이 진짜로 내려가서 다시 꺼내려면 `F8`을 눌러야 하는데,
`H`는 **창이 그 자리에 그대로 있고 투명도만 0**이 됨.
키 입력을 계속 받으니까 `H` 한 번이면 즉시 돌아옴. 반응이 훨씬 빠름.

### 4. 항상 위에 안 뜸

처음엔 항상 맨 위에 뜨게 했다가 뺐음. 다른 창이 위를 덮어야 자연스러움.
문서 작업하다 창 하나 겹쳐놓은 것처럼 보이는 게 목적이라.

## 정직하게 — 이건 못 함

혹시나 해서 적어둠.

- **원격 모니터링 프로그램은 못 피함.** 화면 캡처 방식이든 프로세스 감시 방식이든
  이 프로그램은 아무 대응도 안 함. 그냥 평범한 창임.
- **프로세스 이름도 그대로임.** 작업 관리자 열면 `pythonw.exe`로 보임.

일부러 그 부분은 안 만들었음. 옆자리 시선 정도를 피하는 용도지,
회사 보안 정책을 뚫는 물건이 아님. 그건 다른 얘기고 그렇게 쓸 것도 아님.

## 만들면서 재밌었던 것

여기부터는 코드 얘기임. 게임만 받아갈 사람은 여기서 끊어도 됨.

### 네모로직 500판을 어떻게 넣었나

**500판을 파일로 저장 안 했음.** 레벨 번호를 난수 씨앗으로 써서 그때그때 만듦.
그래서 300번 판은 언제 켜도 똑같이 나오고, 프로그램 크기는 그대로임.

문제는 **아무렇게나 만들면 못 푸는 판이 나온다**는 거임.
정답을 랜덤으로 칠하고 힌트를 뽑으면, 힌트만 봐서는 확정이 안 되고
찍어야만 하는 판이 섞임. 그건 퍼즐이 아니라 그냥 짜증임.

그래서 **줄 논리 풀이기**를 붙였음. 각 줄마다 힌트로 만들 수 있는 모든 배치를 뽑고,
이미 아는 칸과 안 맞는 걸 걸러낸 다음, 남은 배치들이 **공통으로 갖는 칸만** 확정함.
행 → 열 → 행 → ... 더 이상 변화가 없을 때까지 돌림.
끝까지 다 채워지면 "찍지 않고 풀리는 판"인 거고, 아니면 버리고 다시 만듦.

```python
fits = [o for o in options(clue[i], n)
        if all(k < 0 or k == v for k, v in zip(known, o))]
merged = [fits[0][j] if all(f[j] == fits[0][j] for f in fits) else -1
          for j in range(n)]
```

크기(10·15·20)마다 500판씩 **1,500판 전부 돌려서 확인함. 100% 통과.**
대부분 0.01초 안에 만들어짐.

난이도는 밀도로 조절함. 뒤로 갈수록 0.5 쪽으로 밀어서 꽉 차거나 텅 빈 줄이 줄어듦
→ 힌트가 주는 정보가 약해짐 → 어려워짐.

여기서 한 가지 헛다리를 짚었는데, **큰 판일수록 밀도를 더 낮추면 되겠다**고 생각해서
그렇게 해봤더니 정반대였음. 전수 검증이 5.8초에서 80초로 늘고 못 푸는 판이 6개 생김.
성긴 판은 줄마다 가능한 배치 경우의 수가 많아져서 **확정되는 칸이 오히려 줄어듦.**
그래서 크기별로 밀도 하한을 따로 뒀음 — 20x20은 0.60 밑으로 내리면 판 하나 만드는 데
몇 초씩 걸림.

### 소코반은 거꾸로 만듦

소코반은 "풀리는 판 만들기"가 훨씬 어려움. 상자는 밀 수만 있고 당길 수 없어서,
아무데나 놓으면 구석에 처박혀서 못 푸는 판이 되기 쉬움.

그래서 **거꾸로 만들었음.** 다 푼 모습(상자가 전부 목표 위)에서 시작해서
상자를 *당겨서* 흐트러뜨림. 당긴 순서를 뒤집으면 그게 곧 정답이니까
**만들어진 판은 반드시 풀림.** 게임 중에 탐색을 돌릴 필요가 없음.

여기서 버그를 하나 만들었는데, 당기기를 이렇게 짰었음:

```python
boxes.discard(box); boxes.add(back)
man = box            # ← 틀림
```

당기고 나면 사람은 **상자에서 물러난 자리**에 있어야 하는데,
상자가 있던 칸에 놔버림. 사람이 상자를 통과해서 반대편으로 순간이동한 셈이라
되돌릴 수 없는 판이 만들어짐. 검증 돌리니까 7번 판이 딱 걸림.

```
######
###  #
###@ #
#  $.#     ← 상자를 오른쪽으로 밀려면 왼쪽에 서야 하는데
# #  #        거기로 갈 길이 상자로 막혀 있음
######
```

`man = stand`로 고치고 **200판 전부 BFS로 실제로 풀어봐서 확인함. 0개 실패.**
(검증에만 13분 걸림. 상자 4개짜리 9x9는 상태 공간이 커서 완전 탐색이 무거움.
물론 판을 만드는 건 역방향이라 0.01초면 끝나고, 이 탐색은 개발용 확인일 뿐임.)

### 전역 단축키가 안 먹던 이유

`F9`를 눌러도 창이 안 올라왔음. 원인이 두 개였음.

**하나.** `RegisterHotKey`는 `WM_HOTKEY`를 등록한 스레드의 메시지 큐로 보내는데,
메인 스레드에서 등록하면 **tkinter의 메시지 펌프가 먼저 꺼내가 버림.**
아무리 `PeekMessage`를 돌려도 안 잡힘. 전용 스레드에서 등록하고 대기하게 바꿔서 해결.

**둘.** 그리고 더 웃긴 건, 애초에 **`F9`는 이미 다른 프로그램이 쓰고 있었음.**
전역 단축키는 PC 전체에서 한 프로그램만 잡을 수 있음. 키를 쭉 훑어봤더니
`F9`랑 `F12`는 사용 중이고 `F8`, `F7`, `F6`은 비어 있었음.

그래서 기본을 `F8`로 바꾸고, 실패하면 대체 키를 순서대로 자동으로 시도하게 함.
**실제로 어떤 키가 잡혔는지는 메뉴 화면 맨 아래에 항상 표시됨.**
하나도 못 잡으면 빨간 글씨로 알려줌.

### 수박게임 물리

Verlet 적분 + 위치 보정(PBD)으로 직접 짬. 처음엔 과일이 서로 튕겨 나가고,
바닥에 가만히 놓인 과일도 계속 "움직이는 중"으로 잡혀서 게임오버 판정이 안 됐음.

원인은 겹침을 풀 때 **이전 위치까지 같이 옮긴 것**이었음.
Verlet에서 속도는 `현재 위치 - 이전 위치`라서, 이전 위치를 안 건드리는 게
곧 속도 보정이 됨. 그래야 쌓인 과일이 저절로 멈춤.
반대로 **벽·바닥은 이전 위치를 새 위치에 맞춰야** 함. 안 그러면 중력이 만든 속도가
무한히 쌓임. 이 둘을 반대로 해놨던 거였음.

## 구조

```
desk.py          창, 메뉴, 저장, 키 입력
hotkey.py        전역 단축키 (윈도우, ctypes)
games/base.py    공통 인터페이스, 팔레트, 그리기 도구
games/i18n.py    한국어 / English
games/*.py       게임 하나당 파일 하나
smoke_test.py    위의 전부
```

게임은 `reset / key / tick / draw / state / load` 여섯 개만 구현하면 됨.
셸은 어떤 게임인지 전혀 모름. 그래서 열 번째 게임을 넣으려면 **파일 하나 + 목록에 한 줄**이면 끝.

전부 합쳐서 2,800줄 정도. 외부 라이브러리 0개.
