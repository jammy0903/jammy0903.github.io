C 배울 때 제일 힘들었던 게 문법이 아니었음. **코드가 실행될 때 실제로 무슨 일이 벌어지는지** 도저히 이해가 안 갔음.

```c
int *p = &x;
```

*이게 대체 뭔 소리임?* `x`는 메모리 어디에 있음? `p`는 뭘 가리키는 거임? 교재 그림은 그냥 정적이고 추상적인 박스뿐이었음. 직접 **눈으로 보면서** 이해하고 싶었음.

그래서 [**CodeInsight**](https://codeinsight.online) 만들어버림 — 코드 실행 과정을 단계별로 시각화해주는 무료 오픈소스 플랫폼임.

---

## 문제

CS 학생이라면 다 똑같은 벽에 부딪힘:

- **C**: "스택이랑 힙 차이가 뭔데? 포인터 때문에 왜 터지는 거임?"
- **JavaScript**: "왜 `setTimeout(fn, 0)`이 Promise보다 늦게 실행됨? 이벤트 루프가 뭔데?"
- **Java**: "객체가 어디 저장되는 거임? `new` 하면 무슨 일이 생기는 거임?"
- **Python**: "리스트는 참조로 전달됨? 값으로 전달됨?"

Python Tutor 같은 기존 도구들도 좋긴 한데, 그냥 박스랑 화살표 수준이 아니라 **실제 메모리 레이아웃**을 보여주는 걸 원했음. 스택 프레임이 쌓이고, 힙 할당이 일어나고, 포인터가 연결되는 걸 — 실시간으로, 애니메이션으로.

---

## CodeInsight가 뭘 해주냐면

![CodeInsight 데모](https://raw.githubusercontent.com/jammy0903/CodeInsight/main/docs/demo.gif)

코드를 넣으면 실행 단계별로 쪼개줌. 각 단계마다 이런 걸 볼 수 있음:

**C/C++:**
- 전체 메모리 레이아웃 — Stack, Heap, BSS, DATA, TEXT 세그먼트 다 보임
- 변수 할당이랑 쓰레기 값(garbage value)
- 포인터 화살표가 어딜 가리키는지
- 스택 프레임이 쌓이고 사라지는 과정

**JavaScript:**
- 이벤트 루프 시각화 (Call Stack, Microtask Queue, Macrotask Queue)
- 스코프 체인이랑 클로저
- 프로토타입 체인
- Promise 처리 흐름
- 상황별 `this` 바인딩

**Java:**
- JVM 메모리 모델
- 힙의 객체 참조
- 메서드 영역이랑 스택 프레임

**Python:**
- 이름이 객체에 어떻게 바인딩되는지 참조 그래프로 표시
- 가변(mutable) vs 불변(immutable) 객체 동작 방식

## 두 가지 모드 있음

### 1. 레슨 모드
미리 만들어둔 커리큘럼 따라가는 방식임. 각 레슨마다:
- 코드를 단계별로 같이 따라감
- 각 단계에서 AI 설명 붙어있음
- 이해도 확인용 퀴즈도 있음
- 흔히 헷갈리는 포인트도 짚어줌

### 2. 플레이그라운드 모드
직접 코드 짜고 실행되는 걸 지켜보는 모드임. Docker 샌드박스 안에서 코드 돌려서 실행 트레이스 뽑고, 그걸 실시간으로 시각화해줌.

---

## 기술 스택

관심 있는 사람을 위해 정리함:

| 레이어 | 스택 |
|--------|-------|
| 프론트엔드 | React 19, Vite, TailwindCSS, Zustand, Framer Motion |
| 백엔드 | Node.js, Fastify, Prisma, PostgreSQL |
| 실행 환경 | Docker 샌드박스 기반 언어별 시뮬레이터 |
| AI | DeepSeek (단계 설명 생성) |
| 인프라 | Render (프론트엔드 + 백엔드 + DB), pnpm 모노레포 |

구조적으로는 **메타데이터**(DB)랑 **콘텐츠**(JSON 파일)를 분리함. 레슨 메타데이터는 PostgreSQL에 넣고, 실제 단계별 내용은 시작할 때 메모리에 올려두는 JSON 파일로 관리함 — DB 쿼리보다 콘텐츠 조회가 ~100배 빠름.

플레이그라운드에서 코드 실행은 아래 제약이 걸린 Docker 컨테이너 안에서만 돌아감:
- `--network none` (인터넷 접근 차단)
- `--memory 128m` (메모리 제한)
- `--pids-limit 50` (프로세스 수 제한)
- 읽기 전용 파일시스템 + tmpfs
- 실행 전 32가지 금지 패턴 검사

---

## 왜 오픈소스로 만들었냐면

좋은 학습 도구는 무료여야 한다고 생각함. 규칙 암기가 아니라 코드가 어떻게 돌아가는지 **직접 눈으로 볼 수 있어야** 함.

포인터, 클로저, 이벤트 루프 때문에 고생 중인 CS 학생이라면 한번 써봤으면 함. 기여하고 싶은 개발자라면 PR은 언제나 환영임.
